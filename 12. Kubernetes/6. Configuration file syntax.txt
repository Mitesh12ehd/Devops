- Examples:

    nginx-deployment.yaml - file for creating deployment
        apiVersion: apps/v1
        kind: Deployment
        metadata:
            name: nginx-deployment
            labels:
                app: nginx
        spec:
            replicas: 2
            selector:
                matchLabels:
                app: nginx
            template:
                metadata:
                labels:
                    app: nginx
                spec:
                containers:
                    - name: nginx
                    image: nginx:latest
                    ports:
                        - containerPort: 8080

    nginx-service.yaml
        apiVersion: v1
        kind: Service
        metadata:
            name: nginx-service
        spec:
        selector:
            app: nginx
        ports:
            - protocol: TCP
            port: 80        # Service port
            targetPort: 8080 # Container port

Section of kubernetes configuration file:
    
    apiVersion:
        - api version is depends on kubernetes component like deployment, service etc.

    kind:
        - type of component deployment, service etc..

    - There are main 3 sections

    1. Metadata:
        - Describes information about the object.
        - includes:
            name
            labels
            namespace
            annotations


    2. Specification:
        - write every configuration for component
        - attribute of specification is depends on type of component

    3. Status:
        - automatically generated by kubernetes
        - kubernetes update state continuously until we reach desired state
        - kubernetes heal itself until current state is not matches with desired state
        
        - specification provided is desired state
        - status is current state

        ex. 
            status:
                observedGeneration: 1
                replicas: 3
                updatedReplicas: 3
                readyReplicas: 3
                availableReplicas: 3
                conditions:
                    - type: Available
                    status: "True"
                    lastUpdateTime: "2026-01-17T09:30:12Z"
                    reason: MinimumReplicasAvailable
                    message: Deployment has minimum availability.

        Where kubernetes gets data to update status?
            - etcd
            - as a control plane node, etcd hold current status of k8s component

Template:
    - it is subsection in configuration file
    - it has own metadata and specs
    - as pod comes under deployment, in template we define configuration for pods
    - it is blueprint for pods

Labels and selectors:
    - to connect deployment to pods

    Label:
        - define label in metadata sections
        - label is key-value pair

        ex. 
            spec:
                template:
                    metadata:
                    labels:
                        app: nginx

    Selector:
        - to connect our pod to our deployment component
        - label is matched by selector

        ex. 
            spec:
                selector:
                    matchLabels:
                        app: nginx

    - Deployment has its own label defined in main metadata,
        - it is used by service

        nginx-deployment.yaml
            metadata:
                name: nginx-deployment
                labels:
                    app: nginx

        nginx-service.yaml
            spec:
                selector:
                    app: nginx

Ports:
    - it should be configured in service and deployment

    - containerPort (deployment) should match with targetPor(service)
    -  port: 80        # Service port
       targetPort: 8080 # Container port

       Expose Service on port 80, and forward traffic to port 8080 inside Pods

    - Other service send request port 80 to nginx service
    - nginx service send request to port 8080 inside pod.
      
Create deployment and service

    kubectl apply -f nginx-deployment.yaml
    kubectl apply -f nginx-service.yaml

    - Check pod
        - kubectl get pod
        - we have two pods as we defined 2 replicas

    - Check service
        - kubectl get service
        - we can see nginx-service there and it is listening on port 80

    - Check service in details
        - kubectl describe service [service-name]
        - we can check endpoint of pods, ports, selectors
        - there is number of endpoint as number of pods 

    - Check endpoint of each pod
        kubectl get pod -o wide

    - Check status section of configuration file
