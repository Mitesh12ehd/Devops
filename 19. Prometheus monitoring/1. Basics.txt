What is prometheus?
    - it is monitoring tool
    - monitor and alert when crash
    - identify problems before
    - can monitor network load 

Architecture of prometheus:
    
    Prometheus server:
        Storage:
            - time series database
            - store metrics data
            
        Data retrieval worker:
            - pull metrics data
            - retrieve data from applications, services, servers
            - it collect data and push into database

        Accept PromQL queries:
            - accept queries to get stored data for monitor
            - HTTP server
            - Prometheus web UI get data through query

What does prometheus monitor?
    - its called target that prometheus monitor

    - server
    - application
    - services like database

Which units are monitored of those targets?
    - its called metrics
        - CPU status
        - Monitor Memory/Disk space usage
        - Exception count
        - request count
        - request duration
    
    - metrics format is human readable text based
    - metrics entries: TYPE and HELP attributes
        HELP: description of what the metrics is
        TYPE: 3 types
            1. Counter:
                - how many time x happened?

            2. Gauge:
                - What is current value of x now?

            3. Histogram:
                - How long or how big?

How does prometheus collect those metrics from the targets?
    - it pull over http from targets
    - pulls from HTTP endpoint, 
    - endpoint is typically hostaddress/metrics

Target endpoint and Exporters:
    - some servers/components already exposes prometheus endpoints so no extra exporter required
    - Many servers/components require extra component
      that component is called exporter

    - Exporter:
        - it is script that collect info from target and convert that info into format that 
          prometheus can understand
        - and expose that data on /metrics endpoint, where prometheus can scrap it

        Monitor linux server:
            - download node exporter using tar file repository
            - untar and execute
            - convert metrics of the server
            - expose /metrics endpoint
            - configure prometheus to scrap this endpoint

        - exporter is also available as docker image

    - How to create exporter for our own application?
        - Using client libraries(depend on each application tech stack)
        - we can expose endpoint 

Pull mechanism: 
    - prometheus use pull mechanism unlike aws cloudwatch use push mechanism

    - in push mechanism, application and server are responsible for pushing their data to 
      centralized collection platform
    - in pull mechanism, prometheus instance can pull metrics data from server and application

Drawback of prometheus:
    - it is not scalable with large number of nodes 
    - we can setup nested prometheus, prometheus to collect data of prometheus to make it 
      scalable

Prometheus with docker and kubernetes:
    - Fully compatible
    - prometheus component available as docker image
    - can easily be deployed in container environment like kubernetes
