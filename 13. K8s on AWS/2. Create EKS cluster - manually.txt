    Steps:

2. Create VPC for worker node:
    
    Why we need another vpc?
        - EKS cluster needs specific cluster configuration
        - K8s specific and AWs specific networking rules
        - Default VPC is not configured correctly

        - worker nodes need specific firewall configurations
        - best practice: Configure public subnet and private subnet

            - how it is useful?

                Loadbalancer service    <--  Cloud native load balancer  <-- browser request
                (private subnet)             (Elastic load balancer)
                                             (public subnet)

        - to open, port using Nodeport service on worker node
 
    - Our AWS account
        Our VPC
            worker nodes
    
    - AWS managed account
        Other VPC
            control plane node (EKS)

    How do we create this VPC with EKS specific configurations?     
        - by using template cloud formation

    1. Create Cloud formation stack:
        - Go to Cloud formation service
        - Create stack
        - Choose an existing template
        
        - Get url of template:
            - Go to EKS Create VPC docs 
                https://docs.aws.amazon.com/eks/latest/userguide/creating-a-vpc.html
            - here we want to create vpc for public and private subnet
            - public and private subnet > IPV4 > Copy URL

            - validate template
                - hit url 
                - check downloaded yaml file

        - Enter url  
        - We can configure IP for VPC, public and private subnets  (optional)
        - Submit

        - We need this information when creating EKS cluster (Control plane)

3. Create EKS cluster (control plane nodes):    
    - Go to EKS service
    - set name
    - select cluster role that we have created
    - select vpc that we have created
    - select all subnet of that vpc
    - select security groups that is created recently while creating vpc

    Cluster endpoint access:
        - API server is public entrypoint of cluster
        - it is not for request of application
        - it is to connect k8s client (kubectl) to control plane
        - here select public + private 

        public:
            - API server is accessible over the internet.
            - Worker nodes connect via public internet, even though they are inside VPC.

        public + private:
            - API server is accessible over the internet.
            - Privately inside VPC (for worker nodes)

        private:
            - API endpoint accessible ONLY inside VPC.
            - Not accessible from internet.

    Select add-ons:
        - Add
            kube-proxy 
            Amazon VPC CNI 
            CoreDNS

        kubectl cluster-info

5. Create EC2 IAM role for Nodegroup:
    - worker nodes runs worker process
    - kubelet is main process - scheduling, managing pods and communicate with other AWS service
    - kubelet on worker node(EC2 instance) need permission

    Steps:

        - Use case is EC2 > EC2
        - Set policy
            AmazonEKSWorkerNodePolicy
            AmazonEC2ContainerRegistryReadOnly 
            AmazonEKS_CNI_Policy        # container network interface
        - Create role

6. Create Nodegroup and attach to EKS cluster

    - EKS > Our cluster > Compute
    - Node groups 
    - set name
        eks-node-group
    - select node-group role we have created

    - Set compute and scaling configuration:
        - Select amazon linux image
        - Capacity type: On demand (pay for only we use)
        - select t3.small

    - Node group scaling configuration:
        - select number of nodes desired, minimum and maximum
        - it start initially with desired number of nodes, and scale up and down to minimum and maximum 
          accordingly
    
    - Node group update configuration
        - number of node goes to offline when node group update

    - Node group network configuration:
        - select subnets of our vpc

        - enable "Configure remote access to nodes"
        - select ssh key pair (Create or use existing)
        - Allow remote access from
            - selected security groups(for firewall rules)
            - all 

    - check nodes using kubectl
        kubectl get nodes

    - we can scale up and down by updating minimum and maximum nodes

7. Configure auto-scaling:

    How auto scaling works?
        - After creating node group, auto-scaling groups created
        - Check auto-scaling service group
            Our EKS cluster > Compute > Node-group > Autoscaling group name

        Autoscaling group:
            - it has information of minium, maximum limit of instance
            - to scale up and down
            - it is just group, it doesn't auto-scale our resources
        
        - we need to configure K8s auto-scaler that is running inside k8s cluster, that auto-scale our 
          resources
    
        Example:
        - if we have 10 EC2 instance in our cluster, and auto-scaler sees most of the EC2 instance under
          utilized, 
          then it will take pod from 2 EC2 instance and distribute it to rest of them and stop these 2
          EC2 instance
        - If we have 5 EC2 instance and resource run out,
          next pod that to be scheduled can't schedule on any current EC2 instance
          in that case, auto-scaler check our maximum EC2 instance size and start new EC2 instance

    What is required to setup auto-scaler?
        - auto-scaling group
        - create custom policy and attach to Node group IAM role
        - deploy k8s autoscaler
    
    1. Create custom policy:
        - IAM > Policies
        - Create policy
        - JSON
        {
            "Version": "2012-10-17",
            "Statement": [
                {
                "Effect": "Allow",
                "Action": [
                    "autoscaling:DescribeAutoScalingGroups",
                    "autoscaling:DescribeAutoScalingInstances",
                    "autoscaling:DescribeLaunchConfigurations",
                    "autoscaling:DescribeTags",
                    "autoscaling:SetDesiredCapacity",
                    "autoscaling:TerminateInstanceInAutoScalingGroup",
                    "ec2:DescribeLaunchTemplateVersions"
                ],
                "Resource": "*"
                }
            ]
        }
        
        - set name
            node-group-autoscale-policy

    2. Attach policy to existing node-group iam role:
        - Role > node-group role
        - Permissions policies > Add permissions
        - search our custom policy
        - Add

    3. Check tag of auto-scaling group:
        - Auto-scaler group
        - tags
        - here below tags are used by auto-scaler to communicate with auto-scaling group

            k8s.io/cluster-autoscaler/eks-cluster-test
            k8s.io/cluster-autoscaler/enabled

    3. Deploy auto-scaler:
        - kubectl apply -f https://raw.githubusercontent.com/kubernetes/autoscaler/master/cluster-autoscaler/cloudprovider/aws/examples/cluster-autoscaler-autodiscover.yaml

        - it is deployment component.
        - it is created in kube-system namespaces

        - Edit auto-scaler configuration:
            1. Add annotation:
                annotation:
                    cluster-autoscaler.kubernetes.io/safe-to-evict: "false"

            2. Update clustername:
                 spec:
                    containers:
                        - command:
                             - --node-group-auto-discovery=asg:tag=k8s.io/cluster-autoscaler/enabled,k8s.io/cluster-autoscaler/<YOCLUSTER NAME>

                - here update <YOCLUSTER NAME> with our cluster name
                  eks-cluster-test

            3. Add command 
                - Add command below section
                    spec:
                        containers:
                            - command:

                - Add
                    - --balance-similar-node-groups
                    - --skip-nodes-with-system-pods=false

            4. Update kubernetes version:
                - match the version of auto-scaler image with k8s version of our cluster

                - Get out k8s cluster version from AWS EKS UI
                    1.35

                - spec:
                        containers:
                            - command:
                                 image: registry.k8s.io/autoscaling/cluster-autoscaler:-1.35.1

                - here to get exact tag version of image
                    refer https://github.com/kubernetes/autoscaler/tags
