Route 53:
    - It is AWS's DNS(Domain name system)
    - It translate human readable domain ex. google.com into Ip address

    - It is not just DNS, it also does
        - Domain registration (buy domain)
        - Health checking (monitor if your servers are up)
        - Traffic routing (send users to the best/nearest/healthiest server)

    - service name contains 53 because dns listen at port 53

Why it is beyond simple dns?
    - Failover routing — if your main server (US-East) goes down, automatically send traffic to backup server (US-West)
    - Latency-based routing — send European users to your Europe server, US users to US server, automatically
    - Weighted routing — send 90% traffic to old version, 10% to new version (canary deployments)
    - Geolocation routing — show different content based on user's country
    - Health checks — Route 53 pings your servers; if one fails, it stops sending traffic there

Routing policy:
    - setup routing policy based on your needs

Latency based routing:
    - if we send request from europe, it should go to europe server
    - if we send request from india, it should go to india server

    - Create 2 record inside hosted zone with type Latency:
        - in 1 choose europe region, put ip value of europe server
        - in 1 choose india region, put ip value of indian server

DNS record types:
    ## A Record (IPv4)
    Maps a domain name to an IPv4 address.
    Example: www.google.com => 12.34.56.78

    ## AAAA Record (IPv6)
    Maps a domain name to an IPv6 address.
    Example: www.example.com => 2001:db8::1

    ## CNAME Record
    Maps a domain name to another domain name (alias).
    Example: blog.example.com => www.example.com

    ## MX Record
    Directs mail to an email server.
    Example: example.com => mail.example.com (Priority 10)

Use case:
    - Hosting Websites:     Manage domain names and route traffic to web applications.
    - Load Balancing:       Distribute traffic across multiple endpoints using weighted or latency-based routing.
    - Disaster Recovery:    Use health checks and failover routing for high availability.
    - Multi-Region Deployments: Route traffic to the closest region for low latency.
